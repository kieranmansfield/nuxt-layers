# Bug: `typography` layer's new CSS file breaks Tailwind content-scanning in consumer apps

## Where this applies

Repo: `kmcom-nuxt-layers` (github.com/kieranmansfield/nuxt-layers), the layer this
bug is in: `layers/typography`. Introduced between `v2.6.3` and `v2.7.4`.

Found and verified from a consumer project (AG frontend), which currently pins
back to `kmcom-nuxt-layers@2.6.3` in its `package.json` to avoid this bug. This
doc is the handoff to fix it upstream in this repo so the consumer can safely
upgrade to 2.7.4+ again.

## Symptom in the consumer app

- Dev server (`nuxt dev`): visible layout shift shortly after first paint —
  Cumulative Layout Shift score ~0.26 ("Bad", threshold is 0.25). A
  `@nuxt/ui` `UNavigationMenu` header nav visibly resizes from 36px tall to
  64px tall about 800ms-1.2s after the page loads.
- Production build (`nuxt build` + `nuxt preview` / deployed): no visible
  shift, but the nav renders **permanently wrong** — stuck at the 36px/no-padding
  state forever. The dev-mode "shift" is Tailwind's dev JIT scanner eventually
  injecting a missing utility class via HMR; production's one-shot AOT build
  never does that correction, so the bug is silent but permanent there.

## Root cause

`layers/typography/nuxt.config.ts` in v2.7.4 added:

```ts
css: ['#layers/typography/app/assets/css/typography.css'],
```

That new file (`layers/typography/app/assets/css/typography.css`) opens its
**own independent Tailwind build**:

```css
@import 'tailwindcss/theme' layer(theme);
@import 'tailwindcss/utilities' layer(utilities);

@source '../../../../*/app/**/*.{vue,ts}';
@source '../../../../../apps/*/app/**/*.{vue,ts}';
```

This is a second, parallel `tailwindcss/theme` + `tailwindcss/utilities`
import, separate from the one true Tailwind build that `layers/core`'s CSS
already sets up for the whole app. Consumer apps built on this monorepo
(see AG frontend's `app/assets/css/main.css`) already carry an explicit
warning about this exact class of bug:

> `/* tailwindcss + @nuxt/ui are already imported by the core layer's css.
   Importing them again here would just double the Tailwind v4 build pass. */`

Having two independent `@import 'tailwindcss/...'` build roots in the same
Vite module graph causes Tailwind's Vite plugin to lose full content-scan
coverage for classes generated by `@nuxt/ui` components elsewhere in the app
— specifically confirmed missing: the `py-1.5` utility on `@nuxt/ui`'s
`UNavigationMenu` link (`data-slot="link"`), which normally supplies
`padding: 6px 0` and gives the header nav its correct 64px height. With the
second build root present, that utility is not emitted by the main build at
all in production, and in dev mode it only shows up late, via HMR, once
Tailwind's incremental JIT scanner independently notices the class is used.

## Verified evidence (how this was isolated)

Isolation test: same consumer project, same lockfile/dependency state,
_only_ `kmcom-nuxt-layers` version changed.

|                                                             | `@2.6.3`                         | `@2.7.4`                                           |
| ----------------------------------------------------------- | -------------------------------- | -------------------------------------------------- |
| Dev CLS                                                     | 0                                | 0.2606 (reproducible)                              |
| Prod nav height                                             | 64px (correct, from first paint) | 36px (wrong, forever)                              |
| Prod nav link `padding-top/bottom`                          | 6px                              | **0px**                                            |
| Prod nav link `font-size` / `line-height` / `--spacing` var | identical                        | identical                                          |
| Nav DOM markup/classes at both states                       | —                                | byte-identical (ruled out any content/attr change) |

Ruled out before landing on this root cause (do not re-investigate these,
already eliminated with reproducible A/B tests):

- The `ScrollTrigger.refresh()` calls added to
  `layers/scroll/app/plugins/locomotive-scroll.client.ts` in 2.7.4 — disabling
  them made zero difference to CLS (identical value, same DOM nodes shifting).
- `layers/ui` layer source — byte-identical between 2.6.3 and 2.7.4.
- `layers/navigation`, `layers/motion` — no non-test-file source diffs.
- `layers/visual`, `layers/core` non-CSS diffs — all cosmetic (import
  ordering, formatting) or unrelated (new `text-scale` meta tag, unused by
  this symptom — root `<html>` font-size confirmed unchanged at both states).
- Web font loading / FOUT — no font network requests fire at all in this app
  (system font stack), so it isn't a `@font-face` swap.
- `container-type: inline-size` additions in `layers/layout`'s fluid CSS — no
  ancestor of the affected nav element has `container-type` set to anything
  but `normal`.
- `@nuxt/ui` package version itself — pinned identically (`4.10.0`) in the
  consumer app's own `package.json` regardless of `kmcom-nuxt-layers`
  version, so it's not a resolved-version bump of `@nuxt/ui`.

## Suggested fix

Don't give `typography.css` its own `@import 'tailwindcss/theme'` +
`'tailwindcss/utilities'` build root. Instead fold the fluid-type
`@utility text-fluid-*` declarations and `:root` custom properties into the
existing single Tailwind build that `layers/core` already establishes for
consumers — e.g. have `layers/core`'s existing Tailwind-importing CSS file
`@import` this file's _contents_ (theme vars + `@utility` blocks only, no
`@import 'tailwindcss/...'` of its own), or register the utilities via a
Tailwind plugin/config hook instead of a second parallel CSS entry point.

Whatever the mechanism, the acceptance criteria is: only **one**
`@import 'tailwindcss/...'` build root should exist across all layers a
consumer extends, and `@nuxt/ui`-generated utility classes (verify with the
`UNavigationMenu` link's `py-1.5`, but check broadly) must still be present
in a **production** build's output CSS, not just dev.

## How to verify the fix

In a consumer app (or this monorepo's own playground) with `ui: true`
(which transitively pulls in `typography`):

1. `nuxt build && node .output/server/index.mjs` (or `nuxt preview`).
2. Load the page, inspect the header nav's `UNavigationMenu` link element —
   confirm `getComputedStyle(link).paddingTop` is `6px`, not `0px`.
3. Re-run the dev server and use a `PerformanceObserver({type:'layout-shift',
buffered:true})` on page load — confirm no entries (CLS 0), not just that
   it's not visually obvious.
